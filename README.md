# ahava-vechok-study-site

A pipeline for turning a course's lecture decks into a self-contained Hebrew (RTL)
study site, built for the course "אהבה וחוק בעידן טכנולוגי" (Love and Law in the
Technological Era).

**This repository holds the code only.** The course content (lecture text, slide
images, the generated pages and the quiz questions) belongs to the course and its
lecturer, so it is deliberately left out by `.gitignore`. Clone the repo, add your
own `*.body.html` content, and build.

## What the pipeline produces

- **Self-contained pages that work offline.** Images are inlined as data URIs, there
  are no CDN dependencies, and pages open straight from disk.
- **One page per topic.** Each page has:
  - a sticky table of contents, in-page search, dark/light mode and print styles;
  - foldable "my explanation" boxes (💡 note, ⚠️ trap, 🔎 deep-dive), kept visually
    separate from the source's own content;
  - a topic intro panel, lecture-slide figures with click-to-zoom, and prev/next
    navigation.
- **An interactive quiz page.** You click an answer, it marks right or wrong
  instantly, shows an explanation and keeps a running score.
- **Optional shared comments**, stored in Supabase:
  - per-card comments and page-wide notes;
  - visitors can delete only their own comments, and an admin key can delete any;
  - owner tokens never leave the database, because visitors can read only a
    SHA-256 hash of each token.
- **A deploy copy for Netlify** (`site/`), with a strict Content Security Policy,
  `noindex` and a `robots.txt` that blocks crawling.

## Layout

```
_build/
  build.py              body + shell -> page; structural checks
  shell_head.html       CSS + top bar (shared by every page)
  shell_tail.html       JS: search, fold, theme, comments, figure zoom
  assets_slides.py      render whole lecture slides -> <page>_assets.json
  check_wiring.py       every page linked, every anchor resolves
  make_site.py          deployable copy in site/
  render_check.py       headless Chrome -> PNGs, to eyeball the result
  bidifix.py, checkheadings.py, fixmixed.py   RTL / bidi guards
  supabase-setup.sql    comment table, row-level security, delete RPC
  supabase-fix-owner-hash.sql   hash-only owner tokens (included in setup)
  site.example.json     manifest template — copy to site.json
netlify.toml            (generated by make_site.py, git-ignored) publish site/ with CSP headers
```

## Build

```
cd _build
cp site.example.json site.json      # then fill in pages (and optionally "comments")
py -3 build.py <name>               # <name>.body.html -> ../<out>.html
py -3 check_wiring.py
py -3 make_site.py                  # -> ../site/
```

Requires Python 3 with `PyMuPDF` and `Pillow`. `render_check.py` needs Chrome.

## Comments (optional)

1. Create a Supabase project. In the SQL Editor, replace the admin-key placeholder
   in `_build/supabase-setup.sql`, then run the script.
2. Put the project URL and the **publishable** key into `site.json` under
   `"comments": {"url": ..., "anon_key": ...}`, then rebuild.
3. To unlock admin deletes in your own browser, run this once in the console:
   `localStorage.setItem('st2admin', '<your admin key>')`.

`site.json` is git-ignored, so a public repo does not advertise your comment
database.
